# Учёт гаражного кооператива

Flask + SQLAlchemy + SQLite. Роли доступа: `member` (рядовой член), `board`
(член правления), `accountant` (бухгалтер — те же права, что у правления),
`chairman` (председатель) — самая широкая.

## Установка и запуск

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

python seed.py                  # создаст БД (instance/coop.db) и пользователя chairman
python run.py                   # http://127.0.0.1:5000
```

Логин по умолчанию: `chairman` / `change-me-please` — смените пароль в БД
после первого входа (UI для смены пароля пока не сделан, см. раздел «Что дальше»).

## Индексы и внешние ключи

Во всех таблицах на внешние ключи и часто фильтруемые/сортируемые поля
(даты, `full_name`, `year` и т.д.) добавлены индексы (`index=True`), а для
внешних ключей — явные политики `ON DELETE`:
- `CASCADE` — там, где дочерняя запись бессмысленна без родителя (телефоны
  человека, фото/собственники/пломбы гаража, строки разбивки начисления/платежа)
- `SET NULL` — для необязательных ссылок (секретарь/председатель собрания,
  прикреплённый документ, плательщик)
- без явной политики (по умолчанию — запрет) — там, где удаление должно быть
  осознанным действием, а не побочным эффектом (нельзя удалить контрагента,
  человека или вид взноса, если на них ссылаются другие записи)

Дополнительно включена проверка внешних ключей на уровне SQLite (`PRAGMA
foreign_keys=ON` при каждом подключении) — по умолчанию SQLite её не делает,
и без этого все `ondelete`/ограничения целостности просто игнорировались бы.

**Важно:** SQLite не умеет добавлять внешние ключи и их политики в уже
существующие таблицы через `ALTER TABLE` — новая схема применяется только
при создании таблиц с нуля. Если у вас уже есть `instance/coop.db` от старой
версии, удалите её и запустите `python seed.py` заново (данные будут
потеряны). Если в базе уже есть боевые данные, которые нельзя терять, — дайте
знать, сделаю отдельный скрипт-миграцию (пересоздание таблиц с переносом
данных, стандартный приём для SQLite).

## Что уже реализовано

- **Локализация** — русский/английский, переключатель в шапке (без внешних
  зависимостей, простой словарь `app/i18n.py`); даты везде форматируются по
  текущей локали (`fmt_date()`), а не голым ISO
- **Реквизиты кооператива** — ИНН/КПП/ОГРН, площади (кооператива, под
  гаражами, общего пользования); краткое название используется в шапке сайта
  вместо статичного «ГСК»; несколько расчётных счетов (в одном или разных
  банках), с пометкой основного — для будущих платёжек ПД-4
- **Баланс кооператива на дашборде** (правление/бухгалтер/председатель) —
  сумма по всем лицевым счетам (электричество по гаражам + взносы/налоги по
  членам), считается динамически при каждом заходе, нигде не хранится
- **Контрагенты** — список с ИНН, балансом (сумма расходов) и комментарием;
  добавление/редактирование отдельным окном
- **Массовое начисление** (только председатель) — на все лицевые счета членов
  сразу, по коэффициенту гаража либо от общей суммы пропорционально площади,
  либо автоматический расчёт земельного налога по кадастровой стоимости
- **Гаражи** — номер, площадь, приватизация земли, комментарий; собственники
  с долями владения (в них — автоматическое распределение начислений);
  лица для связи; фото гаража с галереей-лайтбоксом (загружает и правит
  только правление/бухгалтер/председатель; комментарий к гаражу тоже видит
  и меняет только правление)
- **Люди** — ФИО, телефоны, адреса регистрации/проживания, email, telegram,
  паспортные данные РФ, даты вступления/выхода из членов кооператива, комментарий
- **Электричество** — счётчик на гараж с историей замен (номер, дата установки,
  дата опломбировки, показания при установке, номер пломбы на счётчике и на
  вводном автомате); актуальным считается последняя запись; отдельный журнал
  показаний (дата снятия, значение)
- **Лицевые счета** — заводятся автоматически при создании гаража
- **Начисления** — по видам взносов (справочник настраиваемый), с автоматическим
  распределением между собственниками пропорционально долям
- **Платежи** — с опциональной разбивкой по видам взносов, если платили «за всё сразу»
- **Документы** — устав/приказы/акты/письма/протоколы, с загрузкой файла
- **Общие собрания** — дата, повестка, секретарь, председательствующий, протокол
- **Роли и доступ** — рядовой член видит только свой лицевой счёт (по привязке
  учётной записи к Person через владение гаражом), правление и председатель — всё

## Что осознанно не реализовано в этой версии (дальнейшие шаги)

- Контрагенты и расходы кооператива (модель `Counterparty`/`Expense` в
  `app/models.py` уже есть, страниц пока нет)
- Правление по созывам (`BoardTerm`/`BoardMember`) и годовые отчёты/сметы
  (`AnnualReport`/`FeeRate`) — модели есть, UI пока нет
- Формирование платёжек ПД-4 с QR-кодом (формат Сбербизнес) — модель
  `PD4Document` заложена, генерация QR и печатной формы не реализована
- Смена пароля пользователем, создание новых пользователей через UI
  (пока — миграция вручную через `seed.py`/консоль)
- Фото гаражей (модель `GaragePhoto` есть, загрузка через UI не сделана)
- Порядок распределения по долям в момент, когда сумма долей ≠ 1 —
  сейчас это просто подсвечивается на странице гаража жёлтым бейджем

## Важно

Код не удалось прогнать end-to-end в песочнице (нет сети для установки
SQLAlchemy), поэтому весь Python синтаксически проверен (`py_compile`), но
перед продакшн-использованием стоит прогнать вручную сценарий: создание
гаража → добавление собственников с долями → начисление → платёж → проверка
баланса.

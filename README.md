# Учёт гаражного кооператива

Веб-приложение для ведения гаражного кооператива: гаражи и собственники,
электроэнергия (показания, тарифы, мониторинг фаз), лицевые счета членов
(взносы, налог, пеня), банковские выписки и реестры, контрагенты, печать
платёжек ПД-4, взыскание долгов через суд, собрания и голосования,
документы, почта и чат правления, доска объявлений, форум, вики,
видеонаблюдение.

Flask + SQLAlchemy + SQLite, миграции — Alembic. Интерфейс на русском и
английском.

Роли доступа (по возрастанию прав): `member` (рядовой член) →
`board` / `accountant` (правление и бухгалтер — одинаковый уровень прав) →
`chairman` (председатель — самая широкая, включая учётные записи и правку
чужих ошибок).

## Быстрый старт

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

python seed.py                  # создаст БД (instance/coop.db), пользователя chairman и базовые виды взносов
python run.py                   # http://127.0.0.1:5000
```

Логин по умолчанию: `chairman` / `change-me-please` — смените пароль сразу
после первого входа в «Мой профиль» → «Изменить пароль» (доступно любому
пользователю для своей же учётной записи; для сброса пароля кому-то
другому — председатель, через «Учётные записи» → «Сбросить пароль», но
только если тот пользователь уже привязан к карточке человека `Person`).
Дальше удобно пройти мастер первоначальной настройки (`/setup`, см.
[docs/features/setup.md](docs/features/setup.md)).

`weasyprint` в `requirements.txt` нужен только для PDF: кнопки «Скачать
PDF» у ПД-4 и документов делопроизводства, формирование заказных писем.
Без него всё остальное, включая печать через браузер (`Ctrl+P`), работает
как обычно; если библиотека не поставится (нужны системные зависимости
Pango/Cairo), просто пропустите её.

`python run.py` — только для локальной разработки. Для реального сервера
(gunicorn, nginx, переменные окружения, cron-скрипты, резервное
копирование) — [docs/deployment.md](docs/deployment.md).

## Разработка

```bash
pip install -r requirements-dev.txt
pytest                                 # полный прогон ~10 минут
pytest tests/test_penalty_amnesty.py   # точечно — по затронутым файлам
```

Каждый тест получает чистую БД, накатанную настоящими миграциями Alembic
(один раз за сессию, дальше — копия файла, см. `tests/conftest.py`), так
что ошибки в самих миграциях тоже ловятся. Новая миграция —
`alembic revision --autogenerate -m "..."`; сгенерированный файл стоит
просмотреть: autogenerate иногда подхватывает посторонние расхождения
схемы, не относящиеся к задаче.

Технический журнал решений и грабель для продолжения разработки —
[context.md](context.md); человекочитаемое описание того, что реализовано,
— в [docs/features/](docs/features/).

# Общение: почта правления, чаты, доска объявлений, форум, вики

[← К оглавлению](../../README.md)

## Почта правления (`/mailbox/`) — веб-интерфейс IMAP/POP3 + SMTP
- Один общий почтовый ящик правления (напр. pravlenie@...), не личная
  почта отдельных членов — председатель один раз вводит параметры
  подключения (`MailboxSettings`, синглтон), правление (BOARD) читает и
  пишет письма через них. Пароль общий для входящих и исходящих, хранится
  зашифрованным (тот же `app/bank_api/crypto`, что и у банка/eWeLink/DVR)
- Стандартные протоколы без привязки к конкретному провайдеру — IMAP или
  POP3 на выбор для входящих (SSL/STARTTLS/без шифрования), SMTP для
  исходящих, только модули стандартной библиотеки Python (imaplib/poplib/
  smtplib/email), новых зависимостей не добавлено. POP3 не поддерживает
  папки протокольно и не хранит флаги «прочитано»/«важное» на сервере (в
  отличие от IMAP) — папок для него в интерфейсе действительно нет, а вот
  статус письма эмулируется (см. ниже, «Точка-индикатор»)
  (см. `app/mail_client.py: IncomingMailClient`)
- **Письма нигде не кэшируются в БД** — каждый просмотр списка/письма/
  вложения открывает живое подключение к серверу и закрывает его в рамках
  одного запроса; хранятся только сами параметры подключения
- Список входящих (пагинация 25/50/100 на страницу), открыть письмо (текст
  или HTML, вложения на скачивание), написать и отправить новое письмо с
  вложениями (SMTP), удалить письмо (IMAP: `\Deleted` + `EXPUNGE`, POP3:
  `DELE`, реально удаляется по `QUIT` в конце сессии — RFC 1939). Ответ/
  пересылка с цитированием — вне этого этапа
- **Папка «Отправленные» — только для IMAP.** SMTP сам не сохраняет копию
  письма никуда, поэтому после успешной отправки она дописывается в
  IMAP-папку через `APPEND` (создаётся, если её ещё нет). Имя папки у
  разных провайдеров разное ("Sent", "Отправленные", "[Gmail]/Sent Mail")
  — председатель указывает его сам в настройках (`MailboxSettings.sent_folder`,
  пусто — копии не сохраняются); сохранение копии best-effort — если не
  получилось, само письмо всё равно считается успешно отправленным. Вкладка
  «Отправленные» видна в UI только если протокол IMAP и папка настроена —
  для POP3 (нет папок вовсе) не показывается. Переход в произвольную папку
  через `?folder=` не даёт — только «Входящие» или настроенная
  «Отправленные» (`app/mailbox.py: _folder_from_request`); так же
  устроены папки «Черновики»/«Спам» (только просмотр) и «Корзина» (при
  удалении письмо перемещается сюда, если настроена, иначе удаляется
  безвозвратно). Список поддерживает поиск (тема/от кого/кому) и
  сортировку по колонке — считаются на стороне приложения по заголовкам
  всех писем папки (`mail_client._filter_sort_paginate`), одинаково для
  IMAP и POP3; письма с вложением отмечены значком 📎 (эвристика по
  IMAP BODYSTRUCTURE, точности не гарантирует)
- **Точка-индикатор статуса письма** (синяя/серая/красная — непрочитано/
  прочитано/важное, клик циклически переключает) — у IMAP это настоящие
  серверные флаги `\Seen`/`\Flagged`, общие для всех членов правления. У
  POP3 таких флагов нет вовсе — статус эмулируется ПЕРСОНАЛЬНО для
  каждого пользователя в таблице `MailboxPop3MessageState` (ключ — POP3
  UIDL, RFC 1939, устойчивый идентификатор письма, в отличие от его номера
  в текущей сессии), и работает только если сервер поддерживает это
  расширение (необязательное по протоколу — если нет, точка для POP3
  просто не показывается). Открытие письма неявно помечает его
  прочитанным — как IMAP-клиент делает обычным (не `PEEK`) `FETCH`
- **Бейдж «непрочитано»** в шапке сайта (меню «Кооператив» → «Почта» и
  у аватара профиля) — обновляется cron-скриптом `scripts/poll_mailbox.py`
  (раз в 5 минут, см. [«Автоматизация»](../deployment.md)) + опортунистически при заходе
  в почту (список/письмо/переключение точки); сам подсчёт НЕ делается на
  каждый заход на сайт — это было бы слишком медленно. IMAP — общий
  счётчик (`MailboxSettings.unread_count`); POP3 — персональный
  (`User.pop3_mailbox_unread_count`, с бутстрапом истории при первом
  запуске для каждого пользователя, см. `scripts/poll_mailbox.py`)
- **HTML-тело письма — недоверенный внешний контент**: своя санитайзация
  через `bleach` (`app/mail_html.py`, whitelist шире, чем у новостей/вики;
  инлайновый `style=` разрешён через `CSSSanitizer` с урезанным списком
  безопасных CSS-свойств — реальная вёрстка почтовых рассылок почти
  всегда на инлайновых стилях, без него ломалась целиком), рендер — в
  `<iframe sandbox="">` вторым эшелоном защиты поверх санитайзера.
  Внешние картинки по умолчанию заблокированы (защита от трекинг-пикселей
  — сам факт загрузки подтверждает отправителю, что письмо открыто, и
  выдаёт IP получателя) — показываются только по явному клику «Показать
  изображения», без проксирования через сервер (сознательный компромисс
  для этого этапа); встроенные (`cid:`) картинки самого письма
  показываются всегда — это не новый сетевой запрос. **Ссылки в письме
  всегда работают** (независимо от того, показаны ли картинки) и
  принудительно открываются в новой вкладке, не внутри iframe письма
- Настройки — модалка на странице списка (`#mailSettingsModal`), тот же
  паттерн, что у подключения к eWeLink: пустое поле пароля в форме = не
  менять; отдельная кнопка «Проверить подключение» (входящие + SMTP) не
  связана с сохранением — можно сохранить настройки, даже если сервер
  сейчас недоступен

## Чат правления и ревизионной комиссии
- Плавающий виджет чата (два независимых — для правления и отдельно для
  ревизионной комиссии) поверх всех страниц сайта у соответствующих ролей;
  можно менять размер и перетаскивать за шапку окна, положение и размер
  запоминаются в браузере отдельно для каждого виджета
- Список участников — статус (онлайн/офлайн/чат открыт сейчас) цветной
  точкой, не текстом; в самих сообщениях — логин автора, не полное ФИО

## Доска объявлений (`/bulletin/`) — куплю/продам/сдам/услуги
- **Раздел ОБЩЕДОСТУПНЫЙ** — виден и анонимному посетителю сайта, как и
  новостная лента и видеонаблюдение (кнопка рядом с ними на странице
  входа, пункт меню для вошедших). В отличие от новостей размещать
  объявление может **любой вошедший пользователь**, не только правление —
  публикуется сразу, без предварительной модерации
- Категории: Куплю / Продам / Сдам / Услуги, фильтр по категории на самой
  странице; необязательное поле цены
- **Контакт для связи — то, что автор сам вписал в само объявление**, не
  подставляется автоматически из его карточки (телефон/telegram/email в
  `Person`) — иначе личные данные утекли бы в открытый интернет без явного
  решения человека на каждый конкретный случай. Имя автора на публичной
  странице тоже не показывается — тот же принцип, что и у новостей
  (автор виден только в журнале аудита)
- Автор может изменить или удалить своё объявление; правление — удалить
  любое (модерация постфактум, по факту жалобы/нарушения, не до публикации)

## Форум (`/forum/`) — свободное обсуждение любых тем
- В отличие от доски объявлений/новостей/видеонаблюдения раздел **НЕ
  общедоступен** — виден только вошедшим членам кооператива (пункт меню
  показывается только им, анонимного посетителя `@login_required`
  отправляет на страницу входа)
- Без разделов/категорий — один общий список тем, отсортированный по
  времени последнего сообщения (не создания темы) — недавно ожившие темы
  всплывают наверх, как в большинстве форумов
- Тему может завести любой вошедший; текст (и темы, и ответов) — та же
  упрощённая markdown-разметка, что у новостей/вики/доски объявлений, с
  тем же тулбаром и AJAX-вставкой картинки прямо в текст
  (`ForumAttachment`, общий редактор вынесен в `forum/_editor.html`, не
  дублируется между формой темы, формой ответа и формой правки)
- Автор может править и удалять своё сообщение; правление может **только
  удалять** чужие темы/сообщения (модерация постфактум, без
  предварительного одобрения), но **не редактировать** чужой текст — по
  прямой просьбе. Первое (открывающее) сообщение темы удаляется только
  вместе со всей темой целиком (иначе тема осталась бы без начала) —
  вместе с темой каскадно удаляются и все её сообщения
- Правление может закрыть тему для новых ответов, не удаляя её (например,
  вопрос исчерпан) — и открыть заново

## Вики (`/wiki`)
Справочные заметки кооператива — в отличие от новостной ленты (хронология
объявлений), это набор страниц-справок, которые правятся по мере
необходимости: параметры подключения к видеонаблюдению, структура сети,
телефоны подрядчиков и аварийных служб и т.п.
- **Дерево разделов/подразделов** (`WikiPage.parent_id`, самоссылающийся
  FK, глубина не ограничена) вместо плоского списка — раздел это обычная
  страница, просто с детьми: у него тоже может быть свой текст, создаётся/
  правится/удаляется той же формой, что и любая страница (кнопка «+
  Добавить подраздел» на странице просмотра и в дереве при наведении).
  Навигация — дерево слева на странице просмотра и на главной `/wiki/`,
  сворачивание веток на Bootstrap `collapse` (без дополнительного JS);
  ветка с текущей страницей раскрыта автоматически, остальные — свёрнуты
  по умолчанию. Сортировка внутри уровня — по алфавиту
- **Удалить раздел с непустыми детьми нельзя** — ни через форму (кнопка
  неактивна, есть подсказка), ни в обход (проверка в `wiki.delete()` до
  похода в БД, и `ondelete="RESTRICT"` на FK как страховка) — сначала
  нужно удалить или перенести подразделы. При выборе родителя в форме
  нельзя выбрать саму страницу или её же потомка (защита от цикла в
  дереве, проверяется на сервере, не только в `<select>`)
- Текст — та же упрощённая markdown-разметка, что и у новостей (жирный,
  курсив, ссылки, списки, заголовок), с той же панелью форматирования, в
  том числе **вставка картинки прямо в текст** кнопкой с камерой — тот же
  механизм, что и у новостей (AJAX-загрузка на лету, POST
  `/wiki/attachments/upload`, `WikiAttachment`); в отличие от новостей у
  вики нет отдельной галереи вложений — картинка живёт только в тексте.
  Технические строки (логин с доменом, punycode-домен и т.п.), которые
  автоматический поиск ссылок в тексте распознаёт неправильно, можно
  обернуть в код (`` `текст` `` или ```` ``` ````-блок) — внутри кода
  ссылки не ищутся вовсе. У любого блока кода при наведении — кнопка
  «Скопировать» в правом верхнем углу; длинный блок дополнительно
  сворачивается под кнопку «Показать полностью»
- Создают/редактируют/удаляют только правление; рядовые члены — только
  чтение
- **Видимость настраивается по каждой странице отдельно**
  (`WikiPage.is_internal`, тот же принцип, что у документов): часть
  заметок (например, телефон аварийной службы) можно сделать доступной
  всем членам, часть (пароли от видеонаблюдения) — только правлению.
  Внутренняя страница не просто скрыта из дерева для рядового члена —
  прямой переход по адресу тоже возвращает 403. **Картинки, вставленные в
  такую страницу, наследуют её видимость** — прямая ссылка на файл тоже
  даёт 403 не-правлению (см. `wiki.attachment()`). Если скрытым сделан
  ЦЕЛЫЙ раздел, а один из подразделов внутри остался общедоступным — этот
  подраздел не пропадает у рядового члена, а поднимается в дереве к
  ближайшему видимому предку (или в корень) — иначе видимая страница
  стала бы недостижимой только из-за того, что раздел над ней сделали
  внутренним (см. `wiki._build_visible_tree`)

**Осиротевшие вложения.** Картинка загружается по AJAX ДО того, как
статья/страница сохранена — если её так и не сохранили (закрыли черновик,
передумали), вложение остаётся «осиротевшим» (`news_id`/`page_id = NULL`).
При сохранении статья «забирает» все вложения, упомянутые в её новом
тексте (и только свои — по автору); если ссылку на картинку из текста
убрали при правке — вложение и сам файл удаляются автоматически. То, что
так и осталось неприкаянным дольше суток, подчищает
`scripts/cleanup_orphan_attachments.py` по cron (см. [«Автоматизация»](../deployment.md)).

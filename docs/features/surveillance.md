# Видеонаблюдение

## Видеонаблюдение (`/surveillance/`) — превью с камер DVR/NVR
- **Раздел ОБЩЕДОСТУПНЫЙ** — виден и анонимному посетителю сайта, без
  входа в систему (по прямой просьбе, так же как новостная лента на
  главной) — пункт меню виден в шапке всем, не только вошедшим (см.
  `base.html`); компактное превью (по одному смонтированному кадру на
  регистратор) есть и прямо на главной странице (`/`, `app/main.py:
  index()`, переиспользует `recorders_with_combined_snapshots()`). Пока
  показывает только периодически обновляемые превью-кадры,
  сгруппированные по регистратору — просмотр живого видео по клику на
  превью не реализован, отдельная задача на будущее
- Регистраторы (DVR/NVR, `DvrRecorder`) и камеры на них (`DvrCamera`,
  канал + номер потока, `channel=N_stream=M.sdp` в пути RTSP регистратора)
  — добавляет/удаляет только председатель (RTSP-логин/пароль —
  чувствительные данные, тот же уровень доступа, что у настроек eWeLink);
  пароль хранится зашифрованным (тот же приём, что у секретов API банка,
  `app/bank_api/crypto.py`). Камеры добавляются сразу в форме создания
  регистратора (динамические строки — кнопка «+ Добавить камеру»,
  без перезагрузки страницы); удаление регистратора удаляет и все его
  камеры, и сохранённые кадры на диске
- Кадр снимается cron-скриптом `scripts/dvr_snapshot.py` раз в минуту
  (см. [«Автоматизация»](../deployment.md)) через системный `ffmpeg`:
  `ffmpeg -y -rtsp_transport tcp -i "<rtsp-url>" -vframes 1 <файл>.jpg`,
  во временный файл с последующим атомарным `os.replace()` в целевой —
  веб-процесс никогда не отдаёт наполовину записанный кадр. Ошибка съёмки
  у одной камеры (недоступна, таймаут) не мешает снять кадры с остальных.
  Кадр отдельной камеры (`instance/dvr/<recorder_id>/snapshots/
  camera_<camera_id>.jpg`, `DVR_SNAPSHOT_FOLDER` в конфиге) отдаётся и сам
  по себе (роут `surveillance.snapshot`, карточка камеры на странице
  раздела), и служит сырьём для следующего шага. Тот же кадр откладывается
  в свою историю на камеру — `instance/dvr/<recorder_id>/history/
  camera_<camera_id>/<метка_времени_UTC>.jpg` — тем же принципом, что и
  история общего кадра регистратора ниже (глубина хранения и подчистка —
  тоже `HISTORY_RETENTION_HOURS`); галерея — `/surveillance/cameras/<id>/history`
- После съёмки всех камер — на КАЖДЫЙ регистратор строится один общий
  смонтированный кадр (сетка из последних кадров всех его камер сразу,
  `_build_combined_snapshot` в `dvr_snapshot.py`, фильтр ffmpeg `xstack`,
  БЕЗ масштабирования — каждая камера в исходном разрешении). Именно этот
  кадр показывается на карточке регистратора и отдаётся роутом
  `surveillance.combined_snapshot` (`instance/dvr/<recorder_id>/combined/
  snapshot.jpg`) — тот же принцип отдачи не статикой, что у документов
  кооператива (`UPLOAD_FOLDER`). Единственная недоступная камера не
  выбивает общий кадр регистратора целиком — берётся её последний удачный
  кадр с диска
- Тот же прогон cron откладывает копию общего кадра регистратора ещё и в
  его историю — `instance/dvr/<recorder_id>/combined/history/
  <метка_времени_UTC>.jpg`, по файлу на снимок. Глубина хранения — сутки
  (`HISTORY_RETENTION_HOURS` в `dvr_snapshot.py`), файлы старше
  подчищаются на каждом прогоне же — отдельного cron для очистки не нужно
- Галерея истории регистратора — кнопка «История» на его карточке
  (`/surveillance/recorders/<id>/combined/history`), самый новый кадр
  первым, клик по превью открывает общий лайтбокс приложения (листать
  кадры этой истории). На главной странице раздела лайтбокса нет: клик по
  склеенному кадру регистратора открывает эту историю, клик по кадру
  отдельной камеры — историю этой камеры
  (`/surveillance/cameras/<id>/history`)

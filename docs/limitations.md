# Ограничения

[← К оглавлению](../README.md)

## Что осознанно не реализовано

- **«Скачать PDF» для платёжки по электричеству гаража** — путь
  `/pd4/print/pdf` пока рассчитан только на счета членов кооператива

## Известные ограничения

- Код синтаксически проверяется в каждой сессии (`py_compile` + Jinja2-
  парсинг всех шаблонов + статическая сверка всех `url_for(...)` с
  реальными маршрутами + сверка всех русских строк со словарём переводов в
  `i18n.py`), и дополнительно end-to-end через `app.create_app()` под
  реальным Flask/SQLAlchemy/Alembic/weasyprint — сеть и зависимости в
  песочнице для этого есть. Ключевые бизнес-сценарии (гараж → собственники
  с долями → показания → начисление → платёж с частичным/полным закрытием
  долга → печать ПД-4 с QR; миграции на БД с реальными данными; расчёты с
  контрагентами включая частичную оплату, правку и сторно платежа) покрыты
  формальным набором автотестов (`pytest`, `tests/`, сотни тестов —
  запускается точечно на затронутые файлы при каждой правке, полностью —
  периодически и перед сдачей крупной задачи), а не только ad-hoc
  HTTP-запросами через `app.test_client()` при разработке — тем не менее
  для нового кода стоит по-прежнему проверять вручную сценарии, которые он
  затрагивает, и добавлять тест, если поведение новое.
- Подробная история изменений по сессиям (что именно менялось в моделях,
  зачем и какие миграции для этого нужны) — в `context.md` рядом с этим
  файлом; он предназначен для следующей сессии продолжения работы над
  проектом, но может быть полезен и как changelog.
- **Интеграция с API Сбербанка (`app/bank_api/`) частично проверена
  вживую кооперативом (тестовый контур), частично — нет.** Подключение
  тестового контура (хост, авторизация через refresh_token, mTLS,
  CA-бандл) исправлено по итогам реальных ошибок при первом подключении —
  подробности каждой находки см. в `context.md`. Не проверены живым
  запросом: промышленный контур (нет доступа для проверки из песочницы
  разработки), и сами ресурсы баланса/выписки/реестров за пределами
  получения токена — собраны по документации. **Формат самих файлов
  реестров (начислений и платежей) — подтверждён реальными образцами
  файлов**, полученными от кооператива, не догадка (см.
  `tests/fixtures/sample_*_registry.*`); он же настраивается на странице
  `/bank-accounts/<id>/registry/format`, если у конкретного подключения
  он отличается. Официальный перечень операций (scope) Sber API не
  содержит явной операции для реестра начислений (только `PAYMENTS_REGISTRY`
  для реестра платежей) — возможно, приём начислений от физлиц не входит
  в этот продукт вовсе, требует уточнения у банка. На этот случай (и на
  случай, если сама механика передачи файла реестра через REST не
  сработает) для реестра начислений/платежей есть независимый от API
  ручной путь: скачать/загрузить тот же файл через веб-интерфейс
  СберБизнес Онлайн (кнопки «Скачать файл реестра» / «Загрузить файл» на
  соответствующих страницах) — баланс и выписка такого запасного пути не
  имеют, только ручной ввод баланса, как было до этой интеграции.
- **Пеня и задним числом внесённые платежи** — если платёж вносится
  позже, чем по соответствующим дням уже была посчитана и начислена
  пеня, пересчёт это не отменяет и не исправляет — досчитывает только
  новые дни вперёд. Если нужно исправить уже начисленную пеню, начисление
  на счёте пени придётся скорректировать вручную.
- **Интеграция с ТНС-Энерго Бизнес (`app/counterparty_api/tns_energo_business.py`)
  проверена целиком живыми запросами** к `lk-b2b-yar.tns-e.ru` с настоящими
  учётными данными кооператива — от RSA-шифрования пароля (сервер
  корректно расшифровывает `__RSA_DATA`) до получения самого баланса
  (сверено с тем, что видно в браузере). Это не документированный API, а
  веб-форма 1С-Битрикс с самодельным RSA-шифрованием пароля на стороне
  браузера (модуль `main.rsasecurity`) плюс отдельный async-компонент для
  самого баланса — оба восстановлены чтением реального кода/разметки
  сайта, не документации. Единственное реально непроверенное — ведут ли
  себя так же личные кабинеты ТНС-Энерго Бизнес ДРУГИХ регионов (не yar):
  общий шаблон Битрикса, скорее всего, идентичен, но не с чем сверить.
  Если для другого региона что-то не сойдётся — ошибки уже разделены по
  типу (неверный логин/пароль от сервера, отказ на запросе баланса,
  не найдено значение в ответе) — понадобится тот же подход, что и при
  диагностике интеграции со Сбербанком выше: посмотреть реальный ответ
  сервера для этого региона.
